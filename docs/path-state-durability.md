# Долговечность состояния авторизации по сетевым путям

Инцидент: [#35](https://github.com/Lomikk/IntersvyazAutomaticWifi/issues/35). Исправление не меняет алгоритм Wi-Fi/captive-авторизации, расписание SMS GET или структуру HTTP-запросов.

## Хранение

- Основной файл: `%LOCALAPPDATA%\IS74Wifi\path-authorization-state.json`.
- Предыдущая **проверенная** версия: `path-authorization-state.json.bak` рядом с основным файлом.
- Каждое сохранение пишет JSON во временный файл и использует атомарную замену `File.Replace(temp, primary, backup)` на NTFS. Успешный коммит оставляет в backup предыдущую генерацию.
- Доступ между процессами сериализуется именованным Windows mutex, привязанным к абсолютному пути файла. При аварийном завершении владелец mutex освобождается ОС.
- Успешная регистрационная очистка удаляет и основной файл, и backup. Старые глобальные timestamps не присваиваются автоматически чужому сетевому пути.

## Ошибки и восстановление

| Ситуация | Поведение |
|---|---|
| Основной файл существует и корректен | Используется он; повреждённая/устаревшая резервная копия игнорируется и обновится при следующей записи |
| Основной повреждён, backup корректен | Восстановление через атомарную запись без перезаписи последней корректной копии; лог `path-state.recovered source=backup` |
| Основной отсутствует, backup корректен | Восстановление из backup, без новой миграции legacy-hint |
| Основной повреждён и backup отсутствует либо повреждён | `InvalidDataException`, оба артефакта сохраняются для диагностики, автоматическая перезапись **запрещена** |
| Возникла временная `IOException` / `UnauthorizedAccessException` при чтении | Ошибка пробрасывается вызывающему коду; не считать отсутствием, не перезаписывать и не восстанавливать из potentially-stale backup |
| Оба файла отсутствуют | Первая инициализация с пустым per-path состоянием и legacy hint как диагностическими данными |

События `path-state.read invalid=primary/backup`, `path-state.read io-error`, `path-state.recovered`, `path-state.initialized` и `path-state.lock abandoned` не содержат SMS, токенов, IP или идентификаторов устройств.

У этой меры есть ограничение: backup содержит **предыдущую генерацию**, а не гарантированно последнюю успешную авторизацию. Если обе копии физически повреждены или удалены, восстановление невозможно. Результаты Windows NTFS/kernel событий не эквивалентны доказанному повреждению файлов.

## Тесты

`pwsh scripts/check.ps1 -Mode Full -SkipBackend -Configuration Release` включает контрактные проверки:
- повреждённый основной JSON без резервной копии: нет молчаливого сброса;
- восстановление после повреждения/удаления основного файла из backup;
- transient sharing violation (Windows) и двойное повреждение;
- конкурентное сохранение 12 сетевых путей без потери сохранённого срока;
- полный сброс регистрации с удалением backup;
- старый формат состояния и прежняя независимость физических путей.

Проверки выполняются **только** в отдельном временном каталоге тестов. Ручное редактирование рабочего состояния не требуется.
