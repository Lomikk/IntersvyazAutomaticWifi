# Windows 11: предупреждения при запуске и обновлении IS74Wifi

IS74Wifi пока распространяется как **экспериментальный неподписанный EXE**. На Windows 11 защитные механизмы могут предупреждать о новом приложении или не разрешать его запуск. Отсутствие цифровой подписи **не доказывает заражение**, но и открытый исходный код или ссылка на GitHub **сами по себе не гарантируют безопасность**.

**Не отключайте защиту Windows автоматически ради IS74Wifi.** Сначала убедитесь, что файл скачан из [официальных релизов проекта](https://github.com/Lomikk/IntersvyazAutomaticWifi/releases), а затем разберитесь, какой именно механизм его остановил.

## 1. Обычный Microsoft Defender SmartScreen

Типичное сообщение: **«Система Windows защитила ваш компьютер»**, приложение не распознано или имеет неизвестного издателя.

Если после проверки источника и контрольной суммы вы осознанно доверяете скачанному файлу, при **обычном предупреждении SmartScreen** обычно можно выбрать **«Подробнее» → «Выполнить в любом случае»**. Возможность может отсутствовать при другой политике защиты или если файл определён как вредоносный.

Не отключайте ради этого Microsoft Defender, защиту в реальном времени или SmartScreen глобально. Если антивирус сообщил о **конкретной угрозе**, а не только о неизвестной репутации программы, не игнорируйте предупреждение: остановитесь и сообщите подробности разработчику.

## 2. Windows 11 Smart App Control

В русской Windows: **«Интеллектуальное управление приложениями»**. Откройте **«Безопасность Windows» → «Управление приложениями и браузером» → «Интеллектуальное управление приложениями»**.

- **Включено**: система может блокировать неподписанные приложения с неизвестной репутацией, в том числе IS74Wifi.
- **Оценка**: система оценивает совместимость; это не то же самое, что активная блокировка.
- **Выключено**: этот механизм не блокирует запуск; если EXE всё равно не запускается, причину нужно искать отдельно.

**У Smart App Control нет разрешения или исключения для отдельного приложения.** Кнопка «Подробнее → Выполнить в любом случае», характерная для SmartScreen, обычно не помогает при жёсткой блокировке Smart App Control.

**Предпочтительное решение:** не ослаблять защиту компьютера; дождаться подписанного выпуска IS74Wifi или отказаться от запуска, если политика Windows его запрещает. Для приложения устойчивое решение — подпись кода доверенным сертификатом (Authenticode). Обычная проверка SHA-256 и отдельная криптографическая подпись манифеста обновления этого не заменяют.

**Если вы всё же рассматриваете отключение Smart App Control:** переключатель «Выключить» расположен в указанном выше разделе «Безопасности Windows». Это **общесистемное снижение защиты**, а не исключение для IS74Wifi. На **старых сборках Windows 11** после отключения для повторного включения может понадобиться сброс или переустановка Windows; в **новых обновлениях** Microsoft разрешила повторное включение из интерфейса. Перед любым изменением проверьте актуальные условия именно для своей версии Windows. Даже после временного отключения и повторного включения система может снова блокировать неподписанный EXE.

Не используйте сторонние «обходчики», реестровые хаки и отключение политики Code Integrity.

Официальные разъяснения Microsoft:
- [Smart App Control — часто задаваемые вопросы](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)
- [Smart App Control для разработчиков](https://learn.microsoft.com/windows/apps/develop/smart-app-control/overview)

## 3. Проверка SHA-256 скачанного EXE

В **Assets** одного и того же [релиза GitHub](https://github.com/Lomikk/IntersvyazAutomaticWifi/releases) скачайте EXE и соответствующий файл `.sha256`.

Откройте PowerShell в папке с файлами и выполните, подставив настоящее имя скачанного EXE:

```powershell
Get-FileHash .\IS74Wifi-v0.1.0-alpha.47-win-x64.exe -Algorithm SHA256
```

Сравните полученное шестнадцатеричное значение `Hash` с первой строкой файла `.sha256` **из того же релиза**. Они должны совпадать без учёта регистра. При несовпадении **не запускайте файл**; скачайте заново или сообщите об ошибке.

**Важно:** опубликованный рядом с EXE SHA-256 выявляет подмену или повреждение относительно опубликованного хэша, но не доказывает личность издателя: злоумышленник с доступом к публикации теоретически может заменить и файл, и его контрольную сумму.

## 4. Приложение перестало запускаться после обновления

Новая версия IS74Wifi — **новый EXE с другим хэшем**. Даже если предыдущий выпуск запускался, обновлённый файл может быть заново проверен и заблокирован SmartScreen или Smart App Control.

1. Установите, что именно блокирует запуск: **SmartScreen**, **Smart App Control** или антивирусная угроза; сохраните текст сообщения и версию Windows.
2. Найдите номер скачанного/установленного релиза и сопоставьте его с [GitHub Releases](https://github.com/Lomikk/IntersvyazAutomaticWifi/releases). Не отключайте защиту ради автоматического обновления.
3. Создайте [Issue](https://github.com/Lomikk/IntersvyazAutomaticWifi/issues), укажите версию IS74Wifi, Windows 11, тип блокировки и приложите скриншот **без личных данных**. Не прикладывайте Bearer, SMS-коды, токены или локальные секреты.
4. Если Windows продолжает блокировать приложение, дождитесь исправленного/подписанного выпуска или помощи с диагностикой. Не рекомендуется пытаться обойти запрет неизвестными скриптами или насильно подменять установленный EXE.

Эта инструкция описывает пользовательские решения и не меняет защитные настройки автоматически.
