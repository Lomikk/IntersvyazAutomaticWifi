# Виртуальная эксплуатация IS74Wifi (первый этап)

`tests/IS74Wifi.SimulationTests` — самостоятельный тестовый проект **в основном
репозитории**. В отличие от изолированных unit-тестов он прогоняет настоящий
`PathAwareAgentCoordinator`, `PathAuthorizationSchedule` и сохраняемое состояние
`PathAuthorizationStateStore` на протяжении месяцев/лет **виртуального времени**.
Алгоритм авторизации не копируется: подменены только внешние probe/runner,
Windows-события и ожидание confirmation/settling (`delayAsync`). В production
используется обычный `Task.Delay`.

На Windows с .NET SDK 10 из корня репозитория:

```powershell
dotnet run --project tests/IS74Wifi.SimulationTests -c Release -- --self-test
dotnet run --project tests/IS74Wifi.SimulationTests -c Release -- --days 30 --runs 2 --seed 74 --paths 2 --strict --json artifacts/simulation/month.json
dotnet run --project tests/IS74Wifi.SimulationTests -c Release -- --days 365 --runs 20 --seed 74 --paths 2 --json artifacts/simulation/years.json
```

* `--days`: 1–36500 виртуальных суток; `--runs`: независимые прогоны с
  детерминированными seed; `--seed` сохраняйте вместе с найденной проблемой.
* `--paths`: 1 или 2 независимых физических адаптера. Первый считается
  предпочтительным. Искусственные адреса — из диапазонов документации.
* `--strict` возвращает ошибку при нарушении *инварианта*; предупреждения об
  ухудшении доступности Интернет сами по себе не ломают сборку.
* `--json`: отчёт для автоматического сравнения прогонов. Значения `seed`,
  метрики и находки воспроизводимы при неизменных runtime и исходниках.
* `--self-test`: два идентичных семидневных прогона для проверки детерминизма
  и базовой активности планировщика.

## Модель мира

Старт — 2026-01-01T00:00Z; каждый адаптер уже авторизован и имеет
сохранённую расчётную границу `T = последняя авторизация + 24 ч`.
Виртуальный сервер независимо истекает возле `T` (обычно смещение −12..+90 с,
редко −60..+300 с). Windows с вероятностью 80% сообщает о событии в пределах
90 с после отключения. Кроме этого модель генерирует ложные NCSI события и
перезапуски агента, а probe и попытки авторизации иногда завершаются
ошибками. Вероятности — характеристики **синтетического** сценария, а не
статистика сети Интерсвязь. Никаких настоящих SMS/HTTP/сетевых операций нет.

Очередь дискретных событий позволяет сразу перейти к следующему сроку,
пробуждению или Windows-событию. Нет реального ожидания суток и нет
подключения к рабочему `LOCALAPPDATA`; состояние каждого прогона создаётся
в отдельной временной папке и затем удаляется. Для защиты CI установлен
предел 500000 тиков и порог 10000 пробуждений за один виртуальный час.

Отчёт содержит количество тиков, probe, попыток `/stepOne`, восстановлений,
перезапусков, инцидентов отсутствия Интернета, максимальный и p95 простой,
непродуктивные тики, `timeline` значимых событий и список `findings`
с точным виртуальным временем. В `timeline` записывается не более 100000
событий; для полного воспроизведения сохраняйте `seed`.
`long_outage` свыше 300 с, `probe_burst` и отсутствие восстановления
спустя 20 минут после Windows-события — **warning**: при позднем отключении и полном
отсутствии события Windows это может быть известным архитектурным
ограничением, а не дефектом кода. `busy_loop`, `step_one_budget`,
`invalid_sleep` — **error**, при `--strict` проваливают проверку.

## Границы достоверности

Это **симуляция логики расписания**, а не полноценная модель всех
компонентов Windows/InterSvyaz. Реальные HTTP длительности, гонка
`stepOne`/push-poll/`stepTwo`, DHCP/VPN маршрутизация, сон ОС, дисковая
ошибка и доставка телеметрии здесь пока не эмулируются; их покрывают
отдельные контрактные тесты или будущие этапы стенда. Текущий
виртуальный `delayAsync` учитывает длительность confirm/settling в
модельных часах, но не подменяет настоящий `Stopwatch` в `AuthorizationFlow`.
Нельзя интерпретировать виртуальную статистику как результаты полевых
измерений. Для следующего этапа нужны инъекции часов/таймеров и транспорта
в `AuthorizationFlow`, затем fault injection для очереди телеметрии.

CI выполняет короткий воспроизводимый прогон; долгие исследования запускаются
вручную и сохраняют JSON артефакты. Не приближать production к тестовой
среде через специальные code paths или сетевые костыли.
